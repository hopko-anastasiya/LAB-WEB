# Де світло

Проєкт з дисципліни «WEB-технології».

«Де світло» — це мапа пунктів незламності: місць, де під час відключень можна погрітися, зарядити
телефон, вийти в інтернет чи просто перечекати. Мешканець відкриває мапу й одразу бачить, які
пункти зараз працюють, що в них є (світло, зв'язок, тепло, генератор, вода) і наскільки вони
заповнені. Оператори пунктів, об'єднані в громади, оновлюють стан звітами з сайту чи через API,
а всі відкриті сторінки отримують зміни наживо.

Застосунок написаний на ASP.NET Core 8 MVC з EF Core 8 і PostgreSQL. Поруч працюють SignalR,
RabbitMQ, Lucene.NET, React-каталог, MCP-сервер і чат-асистент на Google Gemini.

## Як це влаштовано

Чотири основні сутності:

- `Operator` — організація чи людина, що відповідає за пункти;
- `Point` — сам пункт: адреса, координати, графік, місткість, фото, статус;
- `Service` — послуга (зарядка, Wi-Fi, обігрів, генератор…), пов'язана з пунктами «багато до багатьох»;
- `StatusReport` — звіт про стан: чи є світло, зв'язок, тепло, скільки людей, коментар, фото.

Статус пункту (`Working`, `Limited`, `Closed`) бере значення з найсвіжішого звіту. Якщо звіт
відредагували чи видалили, `PointStatusService` перераховує статус заново.

Будь-яку зміну даних ловить перехоплювач EF Core `DataChangesInterceptor` і передає обробникам:
одні розсилають подію через SignalR, інші оновлюють пошуковий індекс і скидають кеш API.

Пізніше з'явилися громади (`Community`) — тенанти застосунку. Кожен оператор належить громаді,
і змінювати пункти можуть лише її учасники. Також додалися користувачі, сповіщення, документ
інструкцій і спільна мапа громади.

### Основа: сторінки, API, тести

**C1.** Для пунктів, звітів, операторів і послуг є звичайні сторінки списку, перегляду, створення,
редагування й видалення. Повідомлення валідації українською, форми захищені antiforgery-токеном.
До пункту й звіту можна додати фото: файл отримує нове ім'я, а старе фото видаляється після
збереження.

**C5, B1.** CRUD доступний через JSON API у `Controllers/Api`, помилки приходять у форматі
`application/problem+json`. Усі списки приймають `skip` і `limit` та повертають
`{ items, skip, limit, total, nextLink }`, а `nextLink` зберігає фільтри запиту. Спільну логіку
(посилання, помилки, сторінки) винесено в базовий контролер `ApiControllerBase`.

**QA1.** Тести на xUnit піднімають застосунок у пам'яті через `WebApplicationFactory` і працюють з
окремою базою `labweb_tests`, яка створюється перед прогоном і видаляється після нього.

> Тестовий проєкт і застосунок підтягували різні версії пакетів EF Core, і збірки починали
> конфліктувати. Тепер версії EF Core явно закріплені в `LabWeb.csproj`.

**C4.** `docker compose up --build` піднімає PostgreSQL, RabbitMQ і застосунок. Образ збирається
в кілька етапів: окремо React-каталог, окремо .NET. Дані бази, фото й ключі лежать у томах.

> Застосунок стартував швидше за PostgreSQL і падав, бо не міг підключитися до бази. Тепер у compose
> є перевірка готовності бази, а Npgsql повторює підключення.
>
> Після кожного перезапуску контейнера злітав вхід: ASP.NET генерував нові ключі Data Protection,
> і старі cookie ставали недійсними. Ключі перенесено в окремий том `keys`.
>
> Коли з'явилися міграції EF Core замість `EnsureCreated`, старі бази вже мали таблиці, але не мали
> історії міграцій. `DatabaseMigrator` розпізнає такі бази й позначає першу міграцію як застосовану,
> тож дані не губляться.

### Мапа й оновлення наживо

**C8.** Мапа на Leaflet і OpenStreetMap показує всі пункти лампочками кольору статусу. Пункти
фільтруються за статусом і за послугами (лишаються ті, де є всі обрані), у спливній картці видно,
що зараз є і скільки людей. На сторінці пункту є міні-мапа, а у формі пункту координати можна
обрати кліком.

**C10, C11.** Хаб `/hubs/points` розсилає зміну пункту чи звіту всім відкритим мапам: через
WebSockets, а якщо вони недоступні, то через long polling. Хаб також рахує, скільки людей зараз
дивляться мапу.

> Спершу розсилку робив один перехоплювач EF Core, і в нього довелося б дописувати кожну нову
> реакцію на зміни. Його розділено: `DataChangesInterceptor` лише збирає зміни, а окремі
> `IDataChangeHandler` розсилають їх у SignalR, оновлюють індекс пошуку й скидають кеш.
>
> Тестовий клієнт SignalR не міг прочитати статуси, бо сервер надсилає їх рядками. У клієнтах
> тестів довелося додати `JsonStringEnumConverter`.

**F2.** Оператор, пункт і населений пункт у формах обираються через Select2: запит іде після трьох
символів із затримкою 300 мс. Довідник із 32 тисяч населених пунктів України з GeoNames
завантажується в базу під час першого запуску, а вибір населеного пункту одразу ставить
координати на мапу.

**B4.** `GET /api/search?q=…` шукає пункти через Lucene.NET за назвою, адресою, послугами,
оператором та описом. Пошук розуміє початок слова («генер» → «Генератор»), одруківки й інші
закінчення («обруч» → «Овруч»). Індекс оновлюється після кожної зміни даних, а поле пошуку є і на мапі.

**B9.** GET-відповіді API кешуються на 5 хвилин через Output Cache з тегами. Будь-яка зміна даних
скидає потрібні теги, тож застарілих статусів API не віддає.

### Користувачі й громади

**C16.** Дивитися мапу може будь-хто, а змінювати дані — лише після входу через Google. Для API
є особистий токен із профілю: його показують один раз, а в базі зберігається лише SHA-256 відбиток.
Cookie сайту для запису в API не приймається.

**B5.** Громада — це тенант. Після входу користувач створює громаду або приєднується за кодом
запрошення. Адміністратор керує учасниками й ролями. Пункти, звіти й операторів чужої громади не
можна змінити ні на сайті, ні через API.

**B6.** Громада має базовий план або Premium. Premium відкриває аналітику й штабну мапу; доступом
керують прапорці Microsoft.FeatureManagement зі своїм фільтром за планом громади.

> Один фільтр мав працювати і за поточним користувачем, і з явно переданим планом, але
> FeatureManagement не дозволяє одному класу бути звичайним і контекстним фільтром одночасно.
> Тому фільтрів два: `PlanFilter` і `ExplicitPlanFilter`.

**QA3.** Тести перевіряють `401` без токена й з хибним токеном, `403` для чужої громади на всіх
операціях запису, заміну й відкликання токена, старт входу через Google, приєднання за кодом і
сторінку «Немає доступу».

> Справжні ключі Google з локальних налаштувань перекривали тестові, і тести входу поводились
> по-різному на різних машинах. Тестові значення тепер задаються змінними середовища в
> конструкторі `ApiFactory`, які мають вищий пріоритет.

### Сторінка пункту, аналітика, штабна мапа

**C6.** Кожен пункт має лендинг `/punkt/{id}`: статус зараз, що є, графік завантаженості за
годинами, останні звіти й мапа. Контакти й кнопка «Маршрут» лишаються внизу екрана під час
прокручування.

**F1.** На сторінці «Аналітика громади» чотири графіки Chart.js: звіти по днях зі світлом і без,
звіти зі світлом за годинами доби, поточне завантаження пунктів і розподіл статусів. Кольори
підібрано під темну тему.

> Графік за годинами показує частку звітів зі світлом, тому одна година з одним звітом може дати
> 100%. Це обмеження вибірки, і на малій кількості звітів його видно.

**C18.** Штабна мапа (`/Board`, Premium) — спільна мапа громади. Учасники наживо малюють лінії,
ставлять примітки й бачать, хто зараз на мапі. Малюнки зберігаються, тож після оновлення сторінки
нікуди не зникають. Текст приміток екранується, тож HTML у ньому не виконується.

### Асистент і MCP

**C21.** `/Assistant` — чат на Google Gemini. Модель сама викликає інструменти застосунку: пошук поруч,
повнотекстовий пошук, стан пункту, його звіти, довідник послуг. Відповідає вона лише за їхніми
даними, з посиланнями на пункти. Відповідь і кроки пошуку надходять потоком через Server-Sent
Events, а кількість запитів обмежена: 20 за 10 хвилин на користувача.

> Модель `gemini-2.5-flash`, з якої почали, виявилася недоступною для нових ключів. Наступна,
> `gemini-3.5-flash`, на безкоштовному плані дає лише 20 запитів на добу, а одне питання витрачає
> 2–3 запити, бо модель спершу викликає інструменти. Тепер використовується `gemini-3.5-flash-lite`,
> а модель можна змінити в налаштуваннях `Ai:Gemini:Model`.
>
> Інколи модель завершувала відповідь, не написавши жодного слова, і чат показував помилку. Тепер
> у такому разі застосунок один раз повторює запит, а тест перевіряє цей сценарій.
>
> Gemini віддавав і свої «думки», але англійською та із сирою Markdown-розміткою, що не пасувало
> до українського інтерфейсу. Думки прибрано, лишились кроки пошуку українською. Курсив і жирний
> текст у відповідях тепер показуються як форматування, а не зірочками.

**C22.** На `/mcp` працює MCP-сервер (Streamable HTTP) з тими самими інструментами для сторонніх
агентів: Claude, Copilot, MCP Inspector. Інструмент `add_status_report` додає звіт і потребує
API-токена в заголовку `Authorization: Bearer`.

> Реєстрація інструментів через `WithTools(typeof(...))` не спрацювала для статичного класу
> інструментів, тому їх реєструє `WithToolsFromAssembly()`.

### Сповіщення, фото, SPA, гра

**B8.** На сторінці пункту можна натиснути «Стежити за пунктом». Коли статус змінюється, подія йде
в чергу RabbitMQ, окремий обробник створює сповіщення для всіх, хто стежить, і в меню з'являється
значок із кількістю нових. Без адреси RabbitMQ (наприклад, у `dotnet run`) використовується черга в пам'яті.

> Сповіщення, надіслані, поки RabbitMQ недоступний, не зберігаються: окремої черги повторів немає.
>
> E2E-тест інколи не бачив значка, хоча сповіщення вже було в списку. Сторінка рахувала нові
> сповіщення раніше, ніж обробник черги встигав їх створити, тож значок з'являвся лише після
> наступного оновлення сторінки. Тест тепер оновлює сторінку перед перевіркою.

**C15.** У формах фото можна перетягнути в поле, воно одразу показується, а завелике зменшується на
canvas до 1600 px і підставляється назад у поле, тож на сервер іде менший файл. Сервер перевіряє не
лише розширення, а й перші байти файлу (JPEG, PNG, WebP), тому текстовий файл з розширенням `.jpg`
не пройде.

**F5.** `/app/` — каталог на React 18 і Vite, що працює тільки через JSON API: список з пошуком,
фільтром і сторінками, сторінка пункту й форма звіту з API-токеном. Адреси працюють як звичайні
посилання, а кнопка «Назад» зберігає пошук.

> `npm audit` показав уразливості в react-router-dom, тож пакет оновлено до 7.18.5, і зауважень
> більше немає.

**F6.** `/Game` — гра «Нічна зміна» на Canvas: ловите каністри, щоб генератор працював, і оминаєте
бурульки. Коли пальне скінчиться, місто згасне. Керування стрілками, A і D або пальцем, рекорд
зберігається в браузері.

### Спільний редактор інструкцій (C12, F3, C13, C14)

`/Guide` — документ громади, який учасники редагують одночасно: як запустити генератор, кого
кликати, де ключі.

- **C12.** Документ складається з рядків-блоків: `# ` на початку робить заголовок, `- ` — пункт
  списку. Enter додає новий рядок, а Backspace у порожньому рядку видаляє його.
- **F3.** Рядки перетягуються за ручку мишею або стрілками з клавіатури.
- **C13.** Кожен блок зберігається на сервері, а зміни розходяться через SignalR-хаб `/hubs/guide`.
  Копія документа лежить у браузері, тож без зв'язку його видно й можна редагувати, а зміни
  надішлються, коли зв'язок повернеться.
- **C14.** Змінені рядки підсвічуються, нові проявляються, переміщені плавно з'їжджають на нове
  місце, а біля рядка видно ім'я того, хто його зараз редагує.

> Коли двоє одночасно відкривали порожній документ, кожен браузер сам створював стартовий рядок,
> і в документі з'являвся зайвий порожній рядок. Помилку знайшов E2E-тест. Тепер стартовий рядок
> створює сервер: у кожної громади він має фіксований ідентифікатор, а вставка в базу пропускає
> дублікат (`ON CONFLICT DO NOTHING`), тож рядок завжди один.

### E2E (QA2)

Сценарії в `tests/e2e` написані на Playwright і запускаються в Chromium. Кожен прогін піднімає
застосунок на порту 5199 з окремою базою `labweb_e2e`. Тести проходять шляхи користувача: мапа й
фільтри, сторінка пункту, створення пункту з фото, звіт, редагування й видалення, зменшення фото,
доступ іншої громади, сповіщення, редактор і штабна мапа у двох браузерах одночасно, офлайн-копія
документа, React-каталог і гра. Після прогону друкується, яку частку коду кожного скрипта
застосунку виконали тести (більшість скриптів — 83–97%).

> Під Node 24 Playwright 1.49 зависав ще до запуску тестів, на завантаженні файлів сценаріїв.
> Після оновлення до 1.56.1 все запрацювало.

## Запуск

Потрібні .NET 8 SDK і PostgreSQL. Скопіюйте `src/LabWeb/appsettings.Local.example.json` у
`src/LabWeb/appsettings.Local.json` і впишіть пароль до PostgreSQL. Цей файл не потрапляє в git,
і туди ж кладуться ключі Google (`Auth:Google`) та Gemini (`Ai:Gemini:ApiKey`).

```bash
dotnet run --project src/LabWeb
```

Сайт відкриється на <http://localhost:5080>. База створюється й заповнюється демо-даними під час
першого запуску. Без ключів застосунок теж працює, але без входу через Google і без асистента. У
режимі Development на сторінці входу є вхід для розробки за email.

React-каталог потрібно зібрати окремо, бо збірка в репозиторій не потрапляє:

```bash
cd src/spa
npm ci
npm run build
```

Усе разом у Docker (сайт на <http://localhost:8080>, панель RabbitMQ на <http://localhost:15672>):

```bash
docker compose up --build
```

Ключі для Docker задаються в `.env` (зразок — `.env.example`).

```bash
cd tests/e2e
npm ci
npx playwright install chromium
npx playwright test
```

Тести xUnit і E2E використовують той самий PostgreSQL, що й застосунок, але власні бази, тож робочі
дані не змінюються.

## Структура

- `src/LabWeb` — застосунок: `Controllers` (MVC), `Controllers/Api` і `Api` (REST), `Hubs` (SignalR),
  `Assistant` (Gemini і MCP), `Messaging` (RabbitMQ), `Search` (Lucene), `Data` (контекст, міграції, демо-дані);
- `src/spa` — каталог на React;
- `tests/LabWeb.Tests` — тести xUnit;
- `tests/e2e` — тести Playwright.
