# Де світло — мапа пунктів незламності

Вебзастосунок для пошуку пунктів незламності та відстеження їхнього стану:
є світло, зв'язок, тепло, наскільки пункт завантажений. Оператори пунктів
надсилають звіти про стан, мешканці бачать актуальну інформацію.

Проєкт виконано в межах курсу «WEB-технології».

## Стек

- ASP.NET Core 8 MVC
- Entity Framework Core 8 + PostgreSQL (Npgsql)
- Bootstrap 5, Bootstrap Icons
- Leaflet + OpenStreetMap (мапа), SignalR (оновлення наживо)
- Lucene.NET (повнотекстовий пошук), Output Cache (кешування API)
- jQuery + Select2 (автодоповнення у формах), довідник населених пунктів GeoNames
- Вхід через Google (OAuth 2.0), API-токени, Microsoft.FeatureManagement (плани громад)
- Chart.js (графіки), React 18 + Vite (каталог-SPA), Canvas (гра)
- Google Gemini (чат-асистент), Model Context Protocol (MCP-сервер)
- RabbitMQ (черга сповіщень)
- xUnit + `WebApplicationFactory` (тести API), Playwright (E2E)

## Предметна область

| Сутність        | Опис                                                        | Зв'язки                                   |
|-----------------|-------------------------------------------------------------|-------------------------------------------|
| `Operator`      | Організація / відповідальна особа                           | 1 → N `Point`                             |
| `Point`         | Пункт незламності: адреса, координати, графік, **фото**     | N → 1 `Operator`, N ↔ N `Service`, 1 → N `StatusReport` |
| `Service`       | Послуга (зарядка, Wi-Fi, обігрів, вода, генератор…)        | N ↔ N `Point`                             |
| `StatusReport`  | Звіт про стан пункту (світло, зв'язок, тепло, люди, фото)   | N → 1 `Point`                             |

Новий звіт автоматично оновлює поточний статус пункту.

## Запуск локально

1. Встановити [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) і PostgreSQL.
2. Скопіювати `src/LabWeb/appsettings.Local.example.json` у `src/LabWeb/appsettings.Local.json`
   і вказати свій пароль до PostgreSQL (файл не потрапляє в git).
3. Запустити:

   ```bash
   dotnet run --project src/LabWeb
   ```

   або відкрити `LabWeb.sln` у Visual Studio і натиснути **F5**.

База `labweb` створюється автоматично під час першого запуску (міграції EF Core) й заповнюється демо-даними.
Застосунок доступний за адресою <http://localhost:5080>.

## Запуск у Docker

Потрібен Docker Desktop (або Docker Engine з Compose). З кореня репозиторію:

```bash
docker compose up --build
```

Застосунок буде на <http://localhost:8080>. Поруч піднімаються PostgreSQL (`db`) і RabbitMQ
(`rabbitmq`, панель керування на <http://localhost:15672>). Дані бази та завантажені фото
зберігаються в томах, тож переживають перезапуск. Образ сам збирає React-каталог. Паролі, порт
і ключі (Google, Gemini) задаються в `.env`: скопіюйте `.env.example` у `.env`.

Зупинити: `docker compose down` (з `-v`, щоб видалити й дані).

## Вхід, громади та плани

Мапу, пункти й звіти бачать усі без входу. Змінювати дані можуть лише учасники **громади**.
Громада — це тенант застосунку: кожен пункт належить громаді через свого оператора, тож учасники однієї
громади не можуть змінити пункти, звіти чи операторів іншої ні на сайті, ні через API.

- **Вхід через Google.** Перший вхід створює обліковий запис. Далі користувач створює нову громаду
  (і стає її адміністратором) або приєднується до наявної за кодом запрошення.
- **Ролі.** Адміністратор громади запрошує учасників, змінює їхні ролі, вилучає з громади та керує
  планом. Довідник послуг змінюють лише системні адміністратори (`Auth:SystemAdmins`, список email).
- **Плани.** У громади базовий план або Premium. Premium відкриває сторінку **Аналітика громади**
  і **Штабну мапу**. Доступом керують фіче-флаги `Analytics` і `SharedBoard`
  (Microsoft.FeatureManagement) із власним фільтром `Plan`, що дивиться на план громади; правило задано
  в `appsettings.json`, секція `FeatureManagement`. Оплата не підключена: план перемикає адміністратор.

### Налаштування Google

1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → **Create credentials →
   OAuth client ID** → тип *Web application*.
2. **Authorized redirect URIs**: `http://localhost:5080/signin-google` (для Docker — `http://localhost:8080/signin-google`).
3. Додати в `appsettings.Local.json`:

   ```json
   "Auth": {
     "Google": { "ClientId": "…apps.googleusercontent.com", "ClientSecret": "…" },
     "SystemAdmins": [ "ваш@gmail.com" ]
   }
   ```

   У Docker — змінні `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SYSTEM_ADMIN_EMAIL` у `.env`.

У режимі Development на сторінці входу є ще **вхід для розробки** (лише email, без пароля), щоб
перевіряти застосунок без Google. В інших середовищах його немає.

### Токени для API

Читати API можна без входу. Для `POST`/`PUT`/`DELETE` потрібен особистий токен. Його створюють
у **Профілі** на сайті; показується він один раз, а в базі зберігається лише SHA-256 відбиток. Новий
токен замінює старий, токен можна відкликати. Cookie сайту для запису в API не приймається.

```bash
curl -X POST http://localhost:5080/api/reports \
  -H "Authorization: Bearer ds_…" -H "Content-Type: application/json" \
  -d '{"pointId":1,"status":"Limited","hasElectricity":false,"hasInternet":true,"occupancy":40}'
```

Без токена — `401`, дані іншої громади або дія без прав — `403`.

## Мапа і статуси наживо

Сторінка **Мапа** (`/Map`) показує всі пункти на OpenStreetMap: колір «лампочки» — статус пункту,
у спливній картці — що зараз є (світло, зв'язок, тепло), скільки людей і послуги. Пункти можна
відфільтрувати за статусом і за потрібними послугами (показуються пункти, де є всі обрані).
Дані беруться з `GET /api/map/points` (параметри `serviceId` можна повторювати, `status`).

Статуси оновлюються без перезавантаження сторінки через SignalR-хаб `/hubs/points`
(WebSockets, із запасним long polling). Будь-яка зміна пункту чи звіту — із сайту чи API —
розсилається всім відкритим мапам подією `pointChanged` (або `pointRemoved`).
Хаб також рахує, скільки людей зараз дивляться мапу (`viewers`).

На сторінці пункту є міні-мапа, а у формі пункту координати можна обрати кліком на мапі.

## Автодоповнення у формах

Випадні списки у формах пункту та звіту замінено на поля з автодоповненням (Select2): варіанти
підвантажуються з сервера після введення 3 символів із затримкою 300 мс.

- **Населений пункт** — довідник із 32 тис. населених пунктів України ([GeoNames](https://www.geonames.org/),
  CC BY 4.0) з українськими назвами та областями. Довідник лежить у `src/LabWeb/Data/settlements-ua.tsv.gz`
  і завантажується в таблицю `Settlements` під час першого запуску. Вибір населеного пункту ставить
  його координати на мапу у формі; якщо пункту немає в довіднику, назву можна ввести вручну.
- **Оператор** (форма пункту) і **Пункт** (форма звіту) шукаються за кількома полями.

Шукаються записи, що містять усі введені слова: `GET /api/lookup/settlements?q=біла київська`,
`/api/lookup/operators?q=`, `/api/lookup/points?q=`.

## Пошук

`GET /api/search?q=…` — повнотекстовий пошук пунктів на Lucene.NET за назвою, населеним пунктом,
адресою, послугами, оператором та описом. Знаходить за початком слова («генер» → «Генератор»),
пробачає одруківки та інші закінчення («обруч» → «Овруч», «бібліотеці» → «бібліотека»), результати
впорядковані за релевантністю (`score`). Параметри: `status`, `skip`, `limit`, відповідь має `nextLink`.
Індекс будується під час старту і оновлюється після кожної зміни пункту, звіту, послуги чи оператора.
Поле пошуку є і на мапі.

## Кешування API

GET-відповіді API кешуються в пам'яті (ASP.NET Core Output Cache, 5 хвилин, окремо для кожного
набору параметрів). Повторна відповідь із кешу має заголовок `Age`. Будь-яка зміна даних
скидає кеш одразу, тож застарілих статусів API не віддає. Довідник населених пунктів не змінюється
і кешується на 6 годин.

## Сторінка пункту

Кожен пункт має окрему сторінку `/punkt/{id}`: статус зараз, що є (світло, зв'язок, тепло, послуги),
графік завантаженості за годинами (Chart.js), останні звіти і мапа. Контакти й кнопка «Маршрут»
лишаються внизу екрана під час прокручування.

## Аналітика і штабна мапа (Premium)

- **Аналітика громади** (`/Analytics`) — графіки Chart.js: звіти по днях зі світлом і без,
  звіти зі світлом за годинами доби, поточне завантаження пунктів, розподіл статусів.
- **Штабна мапа** (`/Board`) — спільна мапа громади: учасники наживо малюють лінії та
  ставлять примітки, бачать, хто зараз на мапі (SignalR-хаб `/hubs/board`).

## Інструкції громади

`/Guide` — спільний документ громади (як запустити генератор, кого кликати тощо), який учасники
редагують одночасно, як у Google Docs. Документ складається з рядків: заголовок (почніть рядок
із `# `), пункт списку (із `- `) або звичайний рядок. Зміни розходяться через SignalR-хаб `/hubs/guide`,
біля рядка видно, хто його зараз редагує. Рядки перетягуються мишею (HTML5 Drag and Drop) або
стрілками з клавіатури. Документ зберігається в базі, а копія лежить у браузері, тож без зв'язку
його видно і можна редагувати: зміни надішлються після повернення зв'язку.

## Сповіщення про зміну статусу

На сторінці пункту можна натиснути **Стежити за пунктом**. Коли статус пункту змінюється, подія
потрапляє в чергу RabbitMQ, окремий обробник створює сповіщення для всіх, хто стежить, і вони
бачать його в розділі **Сповіщення** (значок із кількістю нових у меню).
Без налаштування `RabbitMq:Host` (наприклад, у `dotnet run`) використовується черга в пам'яті.

## Фото

Фото пунктів і звітів зберігаються в `wwwroot/uploads` (у Docker — у томі `uploads`). Сервер перевіряє розмір і
справжній вміст файлу (JPEG, PNG, WebP), а не лише розширення. У браузері (File API) фото можна
перетягнути в поле, воно показується одразу, а завелике зменшується до 1600 px перед відправкою.

## Асистент і MCP

**Асистент** (`/Assistant`, для тих, хто ввійшов) — чат на Google Gemini, який відповідає на питання
на кшталт «де в Харкові працює пункт із генератором?». Модель сама викликає інструменти застосунку
(пошук поруч, повнотекстовий пошук, стан пункту, звіти, довідник послуг) і відповідає лише за
їхніми даними, з посиланнями на пункти. Відповідь і кроки пошуку надходять потоком (Server-Sent
Events). Ключ — `Ai:Gemini:ApiKey` у `appsettings.Local.json` або `GEMINI_API_KEY` у `.env`
([Google AI Studio](https://aistudio.google.com/apikey)); модель — `Ai:Gemini:Model`
(типово `gemini-3.5-flash-lite`). Без ключа сторінка показує, що асистент вимкнений.

**MCP-сервер** на `/mcp` (Model Context Protocol, Streamable HTTP) дає ті самі інструменти
стороннім агентам — Claude, Copilot, MCP Inspector: `search_points`, `find_nearby_points`,
`get_point`, `get_point_reports`, `list_services` і `add_status_report`. Останній додає звіт і потребує
заголовка `Authorization: Bearer` з API-токеном із профілю.

```json
{ "mcpServers": { "desvitlo": { "type": "http", "url": "http://localhost:5080/mcp" } } }
```

## Каталог пунктів (SPA)

`/app/` — односторінковий застосунок на React поверх JSON API: список пунктів зі сторінками,
пошуком і фільтром статусу, сторінка пункту та форма звіту з API-токеном. Адреси працюють як
посилання і кнопка «Назад» (React Router). Джерела — у `src/spa`, збірка кладеться у
`src/LabWeb/wwwroot/app`:

```bash
cd src/spa
npm ci
npm run build
```

## Гра «Нічна зміна»

`/Game` — невелика гра на Canvas: ловіть каністри, щоб генератор працював, і оминайте бурульки.
Коли пальне скінчиться, місто згасне. Керування стрілками або A і D, на телефоні — пальцем;
рекорд зберігається в браузері.

## REST API

JSON API працює поруч із MVC-інтерфейсом за префіксом `/api`. Статуси передаються рядком:
`Working`, `Limited`, `Closed`.

| Ресурс | Методи |
|---|---|
| `/api/points` | `GET` (список), `POST` |
| `/api/points/{id}` | `GET`, `PUT`, `DELETE` |
| `/api/points/{id}/photo` | `POST` (multipart, поле `file`), `DELETE` |
| `/api/points/{id}/reports` | `GET` |
| `/api/reports` | `GET`, `POST` |
| `/api/reports/{id}` | `GET`, `PUT`, `DELETE` |
| `/api/reports/{id}/photo` | `POST`, `DELETE` |
| `/api/operators`, `/api/operators/{id}` | `GET`, `POST`, `PUT`, `DELETE` |
| `/api/services`, `/api/services/{id}` | `GET`, `POST`, `PUT`, `DELETE` |

Фільтри списків: `points` — `q`, `settlement`, `serviceId`, `status`; `reports` — `pointId`, `status`;
`operators` і `services` — `q`.

### Пагінація

Усі списки приймають `skip` (за замовчуванням 0) і `limit` (1–100, за замовчуванням 20):

```http
GET /api/points?status=Working&limit=2
```

```json
{
  "items": [ { "id": 1, "name": "Пункт незламності — Школа №52", "status": "Working" } ],
  "skip": 0,
  "limit": 2,
  "total": 3,
  "nextLink": "http://localhost:5080/api/points?status=Working&skip=2&limit=2"
}
```

`nextLink` зберігає фільтри запиту і дорівнює `null` на останній сторінці.

### Помилки

Помилки повертаються у форматі `application/problem+json`:
`400` — некоректні дані (поле `errors`), `401` — немає токена, `403` — дані іншої громади, `404` — запис не знайдено,
`409` — конфлікт (дубль назви послуги, видалення оператора з пунктами).

### Приклад

```bash
curl http://localhost:5080/api/points?status=Working
```

## Тести

Автотести Web API лежать у `tests/LabWeb.Tests` (xUnit + `WebApplicationFactory`). Вони піднімають
застосунок у пам'яті та працюють з окремою базою `labweb_tests` на тому ж PostgreSQL, що й основна:
база створюється перед прогоном і видаляється після нього.

```bash
dotnet test
```

або **Test → Run All Tests** у Visual Studio.

Що перевіряється: формат сторінки та обхід через `nextLink`, збереження фільтрів у `nextLink`,
некоректні `skip`/`limit`, CRUD усіх сутностей, валідація і коди `400`/`404`/`409`,
завантаження та видалення фото, перерахунок статусу пункту після змін у звітах, дані для мапи
та фільтр за послугами, розсилка змін через SignalR кільком клієнтам одночасно, автодоповнення, повнотекстовий пошук
(префікси, одруківки, оновлення індексу), кешування та його скидання після змін.

Тести автентифікації та авторизації (`tests/LabWeb.Tests/Auth`): `401` без токена чи з хибним токеном,
заміна й відкликання токена, зберігання лише відбитка, `403` для чужої громади на всіх операціях запису
і для користувача без громади, системний адміністратор для довідника послуг, cookie не дає писати в API,
перенаправлення на вхід із `returnUrl`, старт OAuth-потоку Google (редирект на `accounts.google.com`
із `client_id` і `redirect_uri`), прив'язка Google-акаунта до наявного email, приєднання за кодом
запрошення, приховані кнопки й сторінка «Немає доступу» для чужих пунктів, фіче-флаг Premium-аналітики,
зміна плану лише адміністратором, вихід, відсутність входу для розробки поза Development.

Інші тести xUnit: асистент (з підробленою моделлю), MCP-сервер, штабна мапа й інструкції громади
через SignalR, сповіщення через чергу, перевірка вмісту фото, сторінка пункту.

### E2E

Сценарії в браузері лежать у `tests/e2e` (Playwright, Chromium). Вони запускають застосунок на
порту 5199 з окремою базою `labweb_e2e` і проходять шляхи користувача: головна й мапа, сторінка пункту,
створення, редагування й видалення пункту з фото, зменшення фото в браузері, доступ іншої громади,
сповіщення, інструкції та штабна мапа у двох браузерах одночасно, офлайн-копія документа,
React-каталог, гра. Після прогону друкується покриття JavaScript кожного скрипта застосунку.
Потрібні Node.js і той самий PostgreSQL, що для `dotnet test`:

```bash
dotnet build src/LabWeb
cd tests/e2e
npm ci
npx playwright install chromium
npx playwright test
```
